# Step 2 · 主流中间件源码研读

用七周拆解 Qdrant、NGINX、gRPC、RabbitMQ、Envoy、Apache Flink 和 Fast DDS。选取每个项目最能体现其设计约束的一条路径，从接口追到关键状态，再用小实验验证设计边界。

- **节奏**：每天 19:00（Asia/Shanghai）推进一个单元，每课建议 90–120 分钟。每天从路线图取第一个待交付单元，缺席后按课号继续。
- **结构**：每周一个项目，前六天各研究一个机制，第七天用综合实验复盘。共 49 个单元，选题顺序见 [路线图](ROADMAP.md)。
- **语言**：上游源码使用项目自身的语言。实验默认 C++20，Rust 适合直接说明机制时可用 Rust。需要 Linux、容器或外部 broker 时，在课文中写清环境和实测范围。
- **目录**：`week-NN-<project>/00-primer.md` 用于建立直觉。每日交付放在同一周的 `day-NNN-<topic>/README.md` 和 `code/`。课号从 001 单独开始。

## 每课交付

1. 从一个能手工推演的具体例子进入，写清真实负载或故障约束。用 Mermaid 图、时序或状态表说明数据进入系统后经历的关键状态。
2. 每课选一个核心问题，深读一条上游关键路径。标出版本、入口、核心分支和输出或清理点。讲清核心状态或数据结构、不变量、为何这样设计，以及 3–6 条可迁移的做法及其成本和适用边界。源码阅读后，读者应能预测输入或条件变化时，下一步会发生什么。
3. 提供可运行实验，设置一组基线和至少两种不同的边界或取舍。写出实验前的预测、可核对的实测结果，以及结果对应的设计决策。单个代码文件最多 600 行，`main` 负责入口和场景，核心逻辑按职责拆分。
4. 保留接口、测试和观测三个维度的复用清单，安排基础和进阶练习、自测题、模式卡片和下次预习。周复盘至少组合三个本周机制，注入两种故障或边界条件。
5. 在仓库外新建临时目录构建。CMake 使用 `-B`，Rust 使用 `CARGO_TARGET_DIR`。测试结束后清理本次创建的临时目录，失败时也清理。仓库内只保留源码、复现命令和必要的测试结果，课文的运行命令也使用临时构建目录。
6. 构建、运行和检查链接后更新路线图。路线图的完成标记表示课程材料已验证交付，个人学习记录以你自己的笔记为准。
